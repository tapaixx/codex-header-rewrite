Header 名称说明
X-Codex-Turn-State 守卫摘掉确定用不了的回带 state，避免上游报 401 已关闭
关闭先后顺序轮到某个凭证时，插件先看它自己的 State 池：有「该凭证 + 当前模型」的合格 state 就直接覆盖回带值，这一步不经过守卫。只有池子拿不出东西时，才轮到守卫决定摘掉还是放行。开启池子补不上、且回带的 state 确认来自其他凭证或其他模型时，把 X-Codex-Turn-State 摘掉，让上游重新签发一个。关闭池子补不上就原样发出去。来源照常记录、历史照常标注，只是不改这次请求。所以外来 state 真正会发到上游，只剩这几种情况：该凭证没有规则或规则关着；池里还没有它这个模型的 state（刚装插件、刚换号、刚换模型）且守卫关着；或者插件没见过签发它的那次响应，无法证明它是外来的。守卫是这条规则的一部分，不是和「启用改写」并列的开关：规则总开关关掉时，守卫存着也不生效。摘除要「启用改写」+「启用守卫」两个都开；覆盖只要「启用改写」，且没手工设置或移除这个 Header。为什么会有跨号回带：账号不是客户端选的。CPA 的 routing.strategy 默认 round-robin，按请求轮换凭证，session-affinity 默认关闭；换号后客户端并不知情，仍把上一轮的 state 原样带回来。跨模型同理——state 绑在铸造它的模型上。开启后这两种也不摘：只是超过复用窗口（1 小时是经验值），或来源未知。
