State 池

仅显示当前凭证可复用的 X-Codex-Turn-State入池两条判定，各看各的证据：正常请求看回写——注入了 state 而上游没有回写新 state，就是没降智；上游回写了，说明这一轮降智了，回写的那条不入池、注入的那条还会被剔除；没注入就不判定。自动探针开了「多重判断降智」时用同一条规则复核，见探针卡片。正常请求的 state 一律不自动入池，确认可用后在请求详情的「分析」页点「手动入池」；探针拿到的 state 自动入池（开了多重判断则要先通过复核）。判定逻辑集中在插件的 degraded.go。复用每个「凭证 + 模型」保留最新一条；跨号、跨模型都不能复用，超过 200 秒只标记过期。
按凭证维护，改完离开输入框即保存。超过这个时长的 state 标记为过期，仍会注入，探针也会去换新的。任何 state 注入后上游还是降智，就立刻把它从池里清掉。留空按 200 秒。

Cookie 池

判定为不降智的会话 Cookie，按路由目标各留最新一条入池只收有「不降智」判定的会话：开了多重判断、复核通过的探针会话，以及注入了 state 而上游没有回写的线上会话。按 __oailb 里的路由目标去重，同一个路由目标来了新的就覆盖；没有 __oailb 的会话不收。状态由 __oailb 的过期时间决定：没过期就可用。失效注入了 Cookie 的线上请求被判为降智，或探针从池里取的 Cookie 复核判为降智，对应路由目标的那条就置为已失效：还在列表里，但不会再被取用；同一路由目标来了新的不降智 Cookie 就覆盖它。使用自动探针的 Cookie 来源选「Cookie 池」时，随机取一条可用的带上；池里没有可用的就不带 Cookie。

自动 State 探针

按时补池，而不是等降智了才反应做什么按间隔检查探针模型，池里没有 state 或已过期的就补发一次最小 hi 请求（思考强度 low，带哪份 Cookie 由下面的「Cookie 来源」决定）。拿到的 state 连同会话自动入池；打开下面的「多重判断降智」后，要先通过一次复核才入池。何时不跑开关关着、不在生效时段、或者距离上一次真实请求超过下面的活跃判定时间 —— 账号没人用就不该继续烧额度。探针自己的请求不算「真实请求」。与「拦截后重试」互斥，两者都在给同一个池补货。每次探针都是一次计费的真实调用。

降智响应处置

上游返回疑似降智 state 时，对这次响应怎么办拦截判定为降智时（注入了 state 而上游又回写了一个），这次响应不下发给客户端：非流式换成错误对象，流式在第一个数据块换成终止性的 error 事件、其余丢弃，历史标「已拦截」。没有注入 state 的请求不会判定，也就不会被拦截。重试用当前这个凭证和同一个模型，在后台补发内容只有 hi 的最小请求（思考强度 low），只读响应头里的新 state；拿到不降智的就入池，连续几次合并成历史里的一行。按凭证保存，与「启用改写」无关，各自独立生效。插件改不了 HTTP 状态码，客户端看到的是 200 里带错误；被拦截和每次重试，上游都已经计了额度。
